# 井字棋 Asset 阻断根因与费用保护修复

失败作业：`4bd3e28219784599a1426e1dfb8f24bf`。目录 `E:/CubeEngine/CubeEngine-SRTP`，分支 `SRTP`。本轮没有调用模型 API。

## 根因

该次不是服务器繁忙或 Key 错误。模型已经返回内容，Source 在引擎资源编译阶段失败。

1. Rule 第 1 次、Asset 第 1 次都使用 `main.py:起止行@sha256` 引用。提示允许文件/哈希/行引用，却没有提供完整格式，构建器只把字符串当证据 ID；两个有效源引用被错误当作 Unknown evidence ID。Asset 第 2 次因此改成空 evidence，又被拒绝。
2. 源码 `pygame.font.Font(None, 36/25)` 使用 Pygame 自带字体。原资源索引只枚举项目内部文件，未告知模型这个实际存在的依赖资源。模型如实标记必需字体缺失，引擎确实没有导入途径。
3. Asset 编译器把必需 unresolved 和没有资源条目合并成一句报错，同时不允许全程序绘制游戏的空素材清单；没有区分“未完成扫描”和“已确认无需文件素材”。
4. 报告的 unresolved_summary 来自已接受文档/初始占位文档，因 Asset 未接受而漏报真实 `/assets/font`，反而列出尚未执行的 Scene/Input 缺口。
5. 原缓存把引擎代码哈希作为全部复用条件，修复工程代码就可能重新付费生成已合格 Rule。原 attempts 只计阶段生成，不计源码补读；该作业为 6 次阶段尝试加 1 轮源码工具续答，不能把 attempts 当全部 API 请求数。

Rule 第 2 次还出现 outcome condition 类型错误，第 3 次通过三项行为测试。此项属于模型生成规则的修复，不以本次资源修复宣称所有未来模型规则都正确。

## 修复

- SourceWorkspace 直接提供合法 citation 对象；兼容紧凑文件行号引用，仍严格验证文件位置、真实哈希和行范围。
- 在任何模型请求前识别已知运行时依赖；目前支持 `pygame.font.Font(None, ...)` 及普通导入别名。只读取固定安装依赖的数据，不执行游戏代码，不开放任意本机路径。
- 默认字体有明确 URI、真实哈希/大小、导入器和来源信息。模型获得可引用资源记录，Scene 的 font 可引用相应 Asset ID。成功包复制同一字节并验证哈希；已携带字体的包加载时不再回退开发机依赖，丢失/篡改仍报错。
- 显式 resolved 的空资源清单合法；未扫描的初始清单和 required unresolved 继续阻断。不添加占位网格凑资源数，不移除模型的未知语义来假装成功。
- 诊断显示当前候选文档的具体缺口；相同错误经一次修复仍重复则停止花费。
- 新缓存分离输入身份与引擎版本；输入/配置未变时离线重跑当前所有校验与行为门槛，合格才复用付费结果。该用户的旧 Rule 缓存先通过原签名完整核验，再添加新恢复身份；未修改其模型规则内容。
- 单个任务总 HTTP 请求默认上限 12，包含网络重试、源码补读和修复。记录服务返回用量/费用；不承诺请求数等于固定美元数。
