## 2. 把 AI 自對弈管線接入現有 Workbench

AI 程式目前在獨立工作目錄 `E:\CubeEngine\CubeEngine-AI-Dev`（本機檢查時為 `Dev` 分支）：`Coach.py`、`MCTS.py`、`Arena.py`、`training_main.py` 和 3D 井字棋的網路實作構成自對弈 → 訓練 → 新舊模型對決 → checkpoint 的流程。CubeEngine 已有從**合格的 Target Rule IR**編譯 AlphaZero 九個 Game API 的適配層。Workbench 現有的「9-API SELF-TEST」只跑內建符合性案例，**還沒有把當前轉換遊戲送進自對弈訓練**。不要把該按鈕改個名稱便當成管線接入。

本週應完成：

1. 明確串接資料流：Workbench 中當前已批准的 Target Manifest／Rule IR → AlphaZero eligibility／adapter manifest 檢查及封存 → 九 API Game → AI-Dev 的 MCTS／Coach／神經網路 → 自對弈樣本、訓練、Arena 比較及 checkpoint。Rule Runtime 保持玩法和合法動作的唯一權威；不要另寫一套只為井字棋服務的規則。
2. 在 Workbench 提供可見、可控的「自對弈／訓練」入口：顯示當前遊戲是否合格及不合格原因；讓使用者選訓練參數／輸出位置並啟動短程試跑；背景執行、不凍結界面，能看進度、迭代／對局數、結果與錯誤，能安全取消及從相容 checkpoint 繼續。checkpoint、樣本和報告須綁定遊戲 Rule／adapter 的版本與 hash，避免錯載到另一款遊戲。
3. 先以最新生成的 3D 井字棋作完整端到端驗收：Workbench 載入其 Target，通過九 API／eligibility，真正跑至少一輪自對弈與訓練、保存並重新載入 checkpoint，驗證 Arena／對局記錄可重放，確認原本的轉換與遊玩仍正常。神經網路若仍綁定固定的井字棋張量形狀，明確限定首版支持範圍並顯示原因；不要宣稱任意遊戲可訓練。
4. 2048 是單人遊戲，掃雷有隱藏資訊；標準的雙人零和 AlphaZero 管線不能因兩者「轉換成功」就自動套用。Workbench 應清楚顯示不合格原因。若希望日後支持這些遊戲，需要另行設計相應訓練演算法及觀測模型，不在本週用假對手或放寬門檻處理。

**AI 接入完成標準：** 使用者能從現有 Workbench 選定一個合格的已轉換遊戲，啟動並觀察真實自對弈／訓練，取得可重載的 checkpoint 和結果；不合格遊戲有清楚原因。需附一次短程實跑的日誌、樣本／checkpoint 證據、取消／重啟驗證與對原有 Workbench 工作流的回歸結果。
