## 已进入实际代码的改动

1. **源码理解与生成**：默认证据包保留源码片段并遵守预算；新增项目索引、完整入口读取、跨文件分页工具和读取哈希记录。模型只能读取导入项目内的公开文本，不能请求执行命令。原始图片/字体进入资源索引；当前不是视觉模型看图流程。
2. **编译与执行**：默认从一次生成四份大 JSON 改为 Rule → Asset → Scene → Input。每阶段实际编译/执行，失败反馈进入该阶段的有界修复；后续失败保留已通过阶段。跨次调用的阶段缓存绑定源码、素材、编译器、基础 IR 和转换意图的指纹，使用前重新验证。未知规则不再变为 true、空效果或虚构结局。
3. **表达能力**：新增紧凑表达式构建入口，确定性生成 IR AST；禁止 Python eval/任意代码。新增通用序列、一次合并、合并计分、向量和 N 维区域展开函数，供生成规则使用。它们是纯运行时能力，不按游戏名称装载游戏逻辑。这是高层构建 API 的第一部分，还不是任意 Python 游戏程序的完整翻译器。
4. **呈现**：新增消费 Scene/Asset 编译命令的 Ursina 后端，处理节点/预制体/动态实例、坐标矩阵、状态外观、字体与文字、纹理、立方体面贴图、公告板和基本形体。鼠标将选择坐标/实体交给 Input IR；规则仍由唯一运行时执行。未实现的几何配方、碰撞体和缺失状态外观在编译时反馈，不能冒充完整外观。
5. **Workbench**：源码继续走同一编译器；用户提供的完整 `project.manifest.json` 可以直接作为输入，无需伪造原始 Python。只修改 Inspector 尺寸可以发起同一分阶段 Lift，无需额外的自然语言理解请求；有自然语言时按其意图处理。增加阶段进度，移除引导用户附加 Snake 示例包的转换说明。完整 Manifest 包需包含其引用的 IR 与原资源；单个缺依赖 JSON 仍不能运行。
