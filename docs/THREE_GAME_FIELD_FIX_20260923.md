## 井字棋：点击改变规则状态，但棋子不可见

实际最新 Target 的鼠标 press 能落子，棋盘从 0 变为 1/2，状态栏也换手。模型把承载棋子的 quad 缩放为 0.01；后端把 marker 的 0.51/0.57 尺寸再乘该比例，导致棋子几乎不可见。黄色高亮使用无效的 wireframe 属性，实际呈现实心方块。未绑定的键盘 release 还会覆盖有效交互提示。

已修通用后端：cell_center 标记尺寸明确以逻辑格/节点为单位，独立于载体几何的缩放；高亮改用真实线框 Mesh；无绑定释放不覆盖有效提示；鼠标点击共用 press/release 结果选择。

这次用户 Target 原包通过真实渲染检查：27 格射线选取、X/O 可见、空间对角线胜负、回放、重开、相机复位；Manifest 哈希不变。图在 `.cubeengine_llm/backend_checks/current_playability/generated_target_playable.png`。该图是此次真实生成包修复后落两手的截图，不是新调用生成的结果。

## 2048：宿主漏供 session 种子，随后发现生成算法错误

`seed_policy=session` 合法。底层随机服务要求宿主提供 seed，但 Rule/Scene/Input 验收、项目编译和实际游玩都没有提供。要求模型添加 seed 字段不会解决该政策下的宿主问题。

新增统一 session_sources：编译/测试有确定性种子，实际会话获得新种子并保留用于回放。底层 fixed/external/recorded 语义不改。修复覆盖 Manifest 源导入、各阶段检查、项目打开和回放。

原回应还有两项连带问题：

- 比较结果相加的 Python 计数写法，以及 coalesce 简写，之前未正确降低为已支持的严格 IR 表达式；已修。
- 模型提供 fixture 测试棋盘，但测试器静默忽略；现在 Rule/Scene/Input 共用有类型/坐标检查的场景设置，未知测试字段直接报错。

修复后原 Rule 已能编译并执行随机动作/回放，但其自带测试明确失败：模型把 `sequence.merge_equal` 第三个参数写成 4；实际第三参数是倍率，2+2 得到 8，预期为 4。**没有把原模型规则改为 2 来伪造通过。** 模型契约已补齐参数含义及例子，下次恢复会先在本地重验已付费输出，再把这个具体失败反馈给修复阶段。原 2048 Source 尚未完整通过。

## 扫雷：读取工具及 JSON 边界，另有规则缺失

原报告的三次失败依次为读取范围数量、缺少核心规则、JSON Extra data。旧客户端丢弃了最后一次原始文本，因此不能确认该次 Extra data 是两个回答拼接还是单个回答包含多对象，也不能宣称已经重放修复那个原始字符串。

已经修复可确定的管线风险：

- Responses 区分 final 与 commentary，不再把两者拼为一个 JSON；没有明确 final 的多个冲突定义仍拒绝。
- 连续的完整只读 source_requests 对象可以无损合并；不剪掉尾部定义、不接受截断 JSON。
- 失败保存生成文本及通道元数据用于离线诊断，不保存密钥、请求头或推理内容；修复反馈不再误标为上一轮定义。
- 读取工具上限明确为 16 个范围、总字数仍有界；合法 definition 搭配空 source_requests 可结束读取。
- 已读取依赖保留进修复上下文，避免每次重读同样文件并付费。
- 模型契约补齐 flood_region、邻域、首步保护可用方法，以及本地权威状态与画面隐藏的区别；不宣称支持安全的多玩家隐藏信息/AI 观察隔离。

第二次原回应明确缺少揭格、首步保护、胜负和计时等功能。它仍然必须被拒绝；修复传输不等于这份残缺规则自动完成。新的完整扫雷模型结果尚未取得。

协议参考：[OpenRouter Responses API](https://openrouter.ai/docs/api_reference/responses/overview)。本次历史错误的归因以本地保留证据为限。
