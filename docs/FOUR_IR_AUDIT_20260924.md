## 本輪完成

| 範圍 | 確認的問題 | 引擎修復 |
|---|---|---|
| Rule | Python `//` 被直接翻成要求整除的 AST `div`；一般計數／座標換算會在非整除時失敗 | 保留 Python 向下取整語義，包含負數；原有 AST 精確除法契約保持一致 |
| Asset | 規格允許 extrusion `alpha_cutoff=0`，但渲染器只接受 1–255；非圖片及過大圖片可先生成描述檔、到 Scene 才失敗 | 修正生成規格；在 Asset 階段實際解碼並檢查圖片，執行擠出幾何生成檢查，提前修復錯誤資源 |
| Scene | 按壓回饋用節點名稱前綴猜子樹；任意改名或獨立同前綴節點會判錯 | 使用真實邏輯父子關係，與拾取／Input 共用 |
| Input | 生成規格可組合不存在的裝置／控制、鍵盤指標篩選及宿主不發送的焦點／值型別；路由測試僅確認動作存在 | 對齊宿主事件規格；測試還須在行為軌跡中找到能合法執行該動作的狀態 |
| Scene → 三維 → Input | 整體 Cube 排版會解除格子的變換父節點，連帶丟失子樹拾取與父節點可見性 | 保留邏輯父節點，顯示位置仍在統一世界座標；Input、按壓回饋、可見性、碰撞拾取及增量更新都保留邏輯歸屬；動態實例同步保留 |
| 共用生成入口 | 模型把識別碼／型別寫成物件時，部分校驗會先拋 `unhashable dict`，遮蔽 IR 原因 | 依四份現有 wire schema 先檢查整份候選資料；再檢查後端 operand 結構，最後做語義／引用與執行檢查。回報同輪所有獨立結構錯誤；保留合法簡寫、引擎計算資源 hash 及部分欄位修復 |
| Spatial Lift 計畫 | 計畫缺欄位可能在三份後續 IR 都生成完才被發現 | Rule 階段立即檢查並回饋給該階段修復；不繼續生成依賴此計畫的 Asset／Scene／Input |

這些修復沒有遊戲名稱分支。原使用者 Manifest、失敗包與付費缓存沒有被測試資料替換。
