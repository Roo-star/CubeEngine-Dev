## 结论与责任

作业 `5c8a8484fdc94f8b811328db99620b29` 的直接问题是模型生成的 Scene 定义不符合当前引擎要求，不是 API Key、额度或服务器繁忙。模型已经返回内容，失败发生在本地编译。

## 原始失败的证据

- 原报告记录 4 个 HTTP 请求、70,960 输入 token、9,612 输出 token，服务返回费用 0.2643646 美元。它是该作业报告值，不是账户总账单。
- Rule 阶段命中缓存；Asset 阶段通过。Scene 修复依次遇到 geometry 格式、visible、collider shape 等错误。
- 原 Scene 最后响应的 collider 使用 `geometry`，遗漏 `shape/is_trigger/selectable`；相机使用另一套字段；visualizer 矩阵形状不符；binding 的 source/target/transform 缺少引擎要求的判别字段，并夹带不支持的 Rule 表达式。
- 当前离线检查同一原响应得到 **94 条诊断记录**。核心验证器与后端能力验证可能针对同一字段分别报错，因此这不是 94 个独立根因；本次没有截断这些记录。
- 另发现已通过的原 Rule 使用 `winner_state`，运行时原先会忽略它，造成终局没有 winners。现在只把明确引用的全局状态确定性编译为现有 `winners/state.get` 表达式；冲突或未知状态拒绝。真实保存的获胜轨迹现得到 `winners=(1,)`，并记录此编译转换。

脱敏原响应存于 `tests/fixtures/llm_scene_failure_20260923.json`；回放结果存于 [审查证据 JSON](LLM_CONTRACT_AUDIT_20260923.json)。没有把手写 Scene 或参考 Manifest 填成模型结果。

## 为什么旧分支可能不报这个错

本次对照的是本机保存的 `origin/llm`，提交 `1feefe6cd3de795511e2075f54767cade750a26d`，没有联网更新远端引用。

该版本的 `_coerce_collider_properties` 会把缺失或不支持的 shape 改成 `box`，并补上默认 `is_trigger=False`、`selectable=True`。现在的严格路径取消猜测式补值，却没有同步给模型足够明确的规范，这是具体回归原因。旧版“没有报错”不证明其碰撞、呈现与源游戏语义均正确。

## 仍然不能承诺的部分

当前接口使用 **JSON 模式**。精确 schema、能力清单和引用目录进入模型上下文，由本地编译器严格验证；这不是服务端强制完整 IR schema 的 Structured Outputs。模型仍可能违反结构、误解游戏、漏掉生命周期或呈现细节。即使 JSON/IR 全部有效，也不能推导出游戏还原正确。

本轮没有真实生成新的 Scene/Input 或 Spatial Lift 结果，因此不能宣布该井字棋已经完成自动转换，也不能保证下一次或任意一次生成绝无 blocker。允许错误定义通过、把未知 shape 猜成 box、复制参考 Manifest 均不是质量修复。

尚未完成的产品门槛是：真实生成结果的独立源游戏行为/截图对照、五款完整游戏的端到端流程与生命周期覆盖、完整 HUD/布局/外观默认还原，以及相应三维游玩品质。已有独立算法测试和后端能力测试不能替代这些门槛。

工程上的下一步应是使用已保存断点进行**有明确调用上限和验收记录的模型集成测试**，失败响应继续作为离线回归输入；不让用户承担无记录、从头重试的回归测试。请求数上限不是金额保证，服务未返回费用也不能记作免费。本轮没有启动这项付费测试。
