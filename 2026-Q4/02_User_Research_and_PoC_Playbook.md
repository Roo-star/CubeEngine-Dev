## 2. 先决定问题，再选方法

| 想知道什么 | 首选方法 | 原因 |
|---|---|---|
| 对方过去怎样选择、制作或评价相关体验 | 深度访谈 | 需要具体经历、动机、替代和取舍 |
| 第一次看到CubeEngine时懂不懂、记住什么 | 快速访问 | 可以用统一材料快速比较第一反应 |
| 已经发现的偏好或阻碍在更大样本中如何分布 | 问卷 | 适合比较固定选项，不适合首次发现复杂需求 |
| 一群人怎样讨论、解释和互相影响 | 焦点小组 | 适合类别语言、品牌理解和社交传播，不适合个人操作测试 |
| 实际能否完成操作、哪里出错、是否愿意再次使用 | 主持式PoC测试 | 行为比口头“喜欢”更接近真实使用 |
| 是否会主动再来 | 自助体验＋7–14日回访 | 观察一次新奇能否转成第二次行动 |

一场研究只设一个主要目的。深度访谈、完整PoC操作和焦点小组不塞进同一小时完成。

## 3. 参与者怎么选

本阶段不先用“玩家／创作者”两个大标签分配比例，而是按要回答的问题寻找有真实经验的人。候选经验包括：

- 近期亲自玩过或比较过空间游戏、规则变体、策略／解谜游戏的人。
- 近期制作过游戏规则、关卡、交互原型、Game Jam作品或相关工具流程的人。
- 近期评估、采购或采用过游戏工具、技术方案或内容合作的人。
- 能向他人解释游戏机制、创作工具或互动技术的内容作者、教师、活动组织者或策展人。
- 可能提供项目、IP、活动、研究、教育或商业资源的具体合作方。

每位候选人必须写明：`他做过什么｜能回答哪个问题｜适合哪种方法｜从哪里联系｜是否与团队熟悉`。

### 招募来源

| 来源 | 适合什么 | 注意事项 |
|---|---|---|
| Founder／CTO现有人脉与LinkedIn | 首批高信息访谈、专业反馈、转介 | 熟人反馈单独标记，不能全部来自团队关系 |
| 游戏开发、设计、Game Jam、互动媒体社群 | 原型、工具、规则与制作经验 | 先遵守社群规则，不抓取私人名单或群发广告 |
| 棋类、桌游、策略、解谜和空间游戏社群 | 规则理解与体验价值 | 按具体游戏经验筛选，不把整个社群视为同质用户 |
| 香港高校、校友、工作室、活动网络 | 快速访问、焦点小组、PoC参与者 | 记录学生／从业者、熟人／非熟人和招募场景 |
| 线下公共场合或相关活动 | 3–5分钟快速访问 | 只测试第一反应；不把便利样本写成市场代表 |
| 现有参与者转介 | 后续PoC、自助体验和合作线索 | 记录转介链，避免同一朋友圈过度集中 |

## 4. 五种研究的具体做法

### 4.1 深度访谈：30–45分钟

结构：

1. 说明研究目的、时间、是否录音和资料用途。
2. 追问最近一次真实经历，而不是抽象意见。
3. 了解当前做法、替代方案、满意和不满。
4. 了解选择标准、投入、阻碍和放弃原因。
5. 如需展示概念，放在过往经历之后，避免先教育再提问。
6. 记录对方如何复述CubeEngine，以及愿意采取什么下一步。

每次必须得到：至少一个具体经历、一个替代方案、一个取舍、一个反例或阻碍，以及是否适合后续PoC。

避免问题：

- “你喜欢这个想法吗？”
- “如果我们做出来你会买吗？”
- “3D是不是比2D更有趣？”
- 长篇介绍后再问对方是否理解。

应改为：最近一次相关行为、已经花过的时间／钱、真实卡点、实际比较过程和愿意承诺的下一步。

### 4.2 快速访问：3–5分钟

每批使用同一张图、同一段短片或同一句项目说明，并固定四个核心问题：

1. 你觉得刚才看到的是什么？
2. 哪一点最吸引或最困惑？
3. 你认为2D变成3D后改变了什么？
4. 如果想进一步了解，你最想看什么？

不同说明版本分开编号。每个版本尽量收集约50次反应，再比较“正确理解、只记住游戏、只记住AI、只记住3D画面、完全不懂”等结果。

快速访问不收集长篇需求、不讨论复杂价格、不宣称代表市场。线下访问要记录地点、时段和拒绝人数；线上访问记录来源。

### 4.3 问卷：5–7分钟

问卷在完成第一批18次访谈后正式定稿，因为选项应来自真实访谈，而不是团队猜测。

结构：

1. 筛选：近期相关行为、设备、经验和身份场景。
2. 当前行为：玩、制作、选择或分享相关内容的频率与最近一次经历。
3. 替代与阻碍：现在怎样满足同类需求，为什么不改变。
4. 统一材料：所有人看同一版本的图片／短片／说明。
5. 理解与反应：看懂了什么、吸引点、担忧、进一步行动。
6. 可选后续：测试报名、订阅更新或合作联系分别征得同意。

设计规则：

- 一题只问一件事。
- 行为题给明确时间范围。
- 选项包括“不适用、不确定、其他”。
- 先问行为，再问意见。
- 不用“创新、革命性、增强体验”等带倾向词。
- 联系方式与回答数据尽量分表保存。

正式发布前找10–15人试填，让他们边填边解释题意。正式300份有效回答中，要删除重复、关键题缺失、极短时间乱填和不符合筛选条件的回答。

问卷若来自自愿转发和社群招募，只作方向比较；报告必须写明不是随机抽样。

### 4.4 焦点小组：每组6–8人，60–90分钟

四组建议分工：

- 前两组：PoC前的概念理解、吸引力、担忧和自然语言。
- 后两组：PoC出现后的品牌表达、公开材料、转述方式和参与动机。

流程：个人先独立观看并写下第一反应，再进入讨论，避免第一个发言者影响所有人。主持人负责让每个人发言，不追求共识。

焦点小组不用于：判断个人能否操作引擎、处理保密技术细节、估算市场比例或替代一对一敏感访谈。

每组输出：共同语言、明显分歧、被误解的概念、参与者互相说服的方式、最有效和最无效的表达。

### 4.5 主持式PoC测试：30–45分钟

进入测试前必须确认：

- Build可以在非开发环境启动。
- 当前可用Demo、平台、AI状态和已知问题写清楚。
- 测试任务在当前版本确实可完成。
- 录像、事件记录和引用已取得相应同意。
- 展示内容符合已确认的公开／受控边界。

标准流程：

1. 不先解释答案，让参与者复述他认为产品是什么。
2. 给一个真实、具体、当前能完成的任务。
3. 主持人先观察，不立即教；每次帮助都记录。
4. 完成后询问他认为发生了什么、哪里有价值或负担。
5. 提供第二个选择或自由探索机会，观察是否自主继续。
6. 询问是否愿意在版本更新后再次参与。

每场至少记录：启动、任务完成、耗时、错误、主持帮助、理解、规则变化、继续／退出选择、版本和后续同意。

40人次分多批进行。每批约5–8人后整理最严重问题，能够修改的先修改，再进入下一批；不要用40个人重复证明同一个已知故障。

## 5. 多款Demo怎样测试

五款Demo不是五个独立产品，也不要求每个人全部玩完。每款先写一张证明卡：

`来源游戏｜升维后改变的关系｜CubeEngine当前完成的部分｜体验者要完成的任务｜这款Demo能证明什么｜不能证明什么`

测试安排：

- 每位参与者深入完成一款主要任务。
- 根据研究问题轮换不同Demo，避免所有结论只来自井字棋。
- 有条件时允许自由选择第二款，记录自主探索，但不把主持人要求视为主动行为。
- 多款Demo共同证明适用范围和方法重复性；不能由此直接推导市场规模或任意游戏自动转换。

Providence使用独立测试记录。它可以证明CubeUniverse的原创体验和AI bridging方向，不能因喜欢Providence就宣称CubeEngine市场已验证。

## 6. 回访与再次参与

每位PoC体验者记录首次体验日期和可继续访问的窗口。7–14日内检查：

- 是否主动回来。
- 是否在统一提醒后回来。
- 回来做了什么、使用哪个版本。
- 为什么没有回来。
- 是否分享、转介或提出具体下一步。

主动回来、提醒后回来和为获得额外奖励回来分别记录。产品故障、链接失效或版本停用造成的无法回访，不能简单写成“不感兴趣”。

## 7. 最小记录系统

使用现有表格和文件，不买新研究平台。

### 7.1 参与者表

`Participant_ID｜姓名与联系方式（另表）｜招募来源｜熟人/非熟人｜相关经历｜适合方法｜邀请｜回复｜筛选｜预约｜出席｜感谢费｜研究同意｜营销订阅同意｜后续状态`

### 7.2 单次研究记录

`Session_ID｜Participant_ID｜日期｜方法｜主持人｜材料/Build版本｜任务｜原话｜可观察行为｜帮助程度｜完成/退出｜研究员解释｜反例｜待跟进`

### 7.3 问卷记录

`Response_ID｜来源｜问卷版本｜筛选结果｜完成时间｜关键答案｜是否有效｜排除原因｜可选联系ID`

### 7.4 漏斗与回访记录

`Participant_ID｜首次来源｜介绍页访问｜报名｜首次体验｜7–14日再次参与｜主动/提醒｜分享/转介｜合作状态`

### 7.5 修改记录

`问题｜证据ID｜修改前版本｜决定｜修改后版本｜再次测试对象｜结果｜剩余问题`

## 8. 每周分析

每周固定一次60–90分钟分析：

1. 删除无效和重复资料。
2. 按方法、来源、经验、版本和熟人／非熟人分组。
3. 列出本周最重要的三个发现和至少一个反例。
4. 区分产品问题、传播问题、招募问题和技术故障。
5. 只选择一个下周必须修改或进一步验证的重点。

描述结果时写清分母，例如“本轮8位参与者中5位……”，不能写成“62.5%的市场……”。

## 9. 什么时候调整数字

00中的计划目标不是为了机械凑数。只在10月16日和11月13日集中调整：

- 新访谈是否仍产生新的重要信息。
- 哪些经验类型仍未覆盖。
- 问卷是否严重偏向同一来源。
- PoC是否因为技术故障而无法回答原问题。
- 招募和主持是否超过20小时／周容量。

若必须削减，按00的顺序削减：新平台、额外内容、第四组焦点小组、超过200份后的问卷、超过100人的自助体验。保留深度访谈、主持式PoC、再次参与和修改后回测。
