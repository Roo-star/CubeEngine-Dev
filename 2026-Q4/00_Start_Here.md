## 1. 到年底的执行与绩效指标

商业目标与SMART Marketing目标见01。本节是截至12月4日完成主要招募和测试、12月11日完成数据整理的执行量与绩效指标，不是另一套目标。人数可以在不同方法之间重叠，但“独立参与人数”必须去重。

| 工作 | 计划目标 | 最低有效线 | 为什么是这个数字 |
|---|---:|---:|---|
| 深度访谈 | 36人 | 30人 | 分三轮了解概念、PoC反馈和商业／合作场景。单一、较集中的问题通常需要约16–24次访谈才能形成较深入理解；本项目对象和阶段更多，因此总目标提高到36人 |
| 主持式PoC测试 | 40人次 | 30人次 | 每次让参与者实际完成任务并观察问题。每个主要版本／任务用约5–8人快速发现问题，跨多个版本和对象累计约40人次 |
| PoC独立体验者 | 100–150人 | 75人 | 包含主持式和自助体验，按人去重；其中40人次接受主持式观察。用于观察启动、完成、退出和再次使用，不称为留存或PMF |
| 7–14日内再次参与 | 25人 | 15人 | 检查一次好奇能否转成第二次行动；区分主动回来和收到提醒后回来 |
| 5–7分钟问卷 | 300份有效回答 | 200份 | 用来比较已通过访谈发现的选项和模式；主要作方向判断，不冒充随机代表性调查 |
| 3–5分钟快速访问 | 150人 | 100人 | 用统一图片、短片或一句说明快速测试理解、兴趣点和记忆；不代替深度访谈 |
| 焦点小组 | 4组，每组6–8人 | 3组，每组6–8人 | 用于观察人们如何讨论、解释和互相传播这个新概念；不用于测试个人操作流程 |
| 有明确主题的合作交流 | 10次 | 6次 | 对象可以是工作室、IP方、活动方、教育／研究方或内容转译者；必须讨论具体场景 |
| 形成明确下一步的合作 | 3项 | 1项 | 下一步可以是二次会议、提供项目、联合展示或试点；交换名片不算 |

数字的用途不同，不能混在一起：

- 深度访谈回答“为什么”和“在什么情境下”。
- 问卷回答“已经发现的模式在更大样本中如何分布”。
- 快速访问回答“第一眼是否看懂、记住什么”。
- PoC测试回答“实际能不能操作、哪里卡住、是否愿意再来”。
- 焦点小组回答“人们怎样共同讨论和转述这个概念”。

36次访谈不是集中在PoC之前完成；40次PoC测试也不是一轮做完。它们分阶段进行，问题和材料会随版本变化。

## 2. 五个执行阶段

### 阶段一｜09/17–10/02：产品出来前，先把问题和第一批人找对

目标：理解外部人怎样看待“游戏升维”、当前替代做法和CubeEngine概念，并为PoC测试准备合格参与者。

要做：

1. 完成访谈提纲、快速访问卡片、问卷草稿和统一记录表。
2. 09/21–22先做2次试访，修改问题后再正式进行。
3. 完成18次深度访谈。
4. 完成50次3–5分钟快速访问。
5. 完成2组焦点小组，每组6–8人；只讨论概念理解、吸引力、担忧和表达方式，不展示不能公开的技术。
6. 用10–15人试填问卷，只检查题目是否清楚；这批不计入正式300份。
7. 招募并确认第一轮PoC候选人，目标至少25人，以防临时取消。
8. 建立一个统一介绍／报名页面，能够收集测试兴趣和自愿联系方式。

阶段交付：18份访谈记录、50份快速访问、2组讨论记录、修订后的研究材料、首批PoC名单、统一报名入口。

### 阶段二｜10/03–16：第一轮PoC测试，同时启动问卷和第一轮认知传播

目标：知道别人能否看懂、相信并操作CubeEngine，以及升维体验的主要价值和障碍。

要做：

1. 完成20人次主持式PoC测试，分成至少两小批；第一批发现问题后先修改，再做下一批。
2. 开放第一版自助体验；主持式与自助合计累计至少30名独立体验者。
3. 正式发布问卷，取得首批100份有效回答。
4. 再做50次快速访问，累计达到100人；重点比较两种不同的项目说明或演示顺序。
5. 发布或定向发送4–6件核心材料：项目说明、前后对照、真实操作、一个具体规则变化及参加测试的方法。
6. 10月16日完成第一次判断：谁最能理解、哪种证明最可信、必须修什么、是否可以扩大公开。

阶段交付：20次PoC观察、30名以上独立体验者、100份问卷、100次累计快速访问、第一轮修改记录、公开范围决定。

### 阶段三｜10/19–11/13：第二轮PoC、扩大问卷、正式建立漏斗

目标：验证修改是否有效，并把“看到”逐步转成报名、体验和再次参与。

要做：

1. 新增10次深度访谈，累计28次；重点补第一轮出现分歧的对象和使用场景。
2. 新增20人次主持式PoC测试，累计40人次；其中安排部分旧参与者回测修改版本。
3. 主持式与自助合计累计达到75名独立体验者。
4. 问卷新增200份，累计达到300份有效回答。
5. 再做50次快速访问，累计150人。
6. 完成另外2组焦点小组，累计4组；重点测试品牌语言、转述方式和公开内容。
7. 发布6–8件由同一批真实素材拆出的内容，并完成至少30次有对象、有理由的定向外联。
8. 接触前5个具体合作对象，记录其关注点、反对意见和下一步。
9. 11月13日决定：保留哪些对象、内容和渠道；停止哪些无效动作。

阶段交付：40次累计主持测试、300份问卷、150次快速访问、4组焦点小组、75名累计体验者、第二轮产品／表达修改、初步渠道比较。

### 阶段四｜11/16–12/04：扩大有效动作，完成市场结论

目标：把已经有效的触达和体验方式重复一轮，补足商业和合作信息，并在报告写作前停止大规模新增样本。

要做：

1. 新增8次深度访谈，累计36次；重点访问已经浮现的优先对象、潜在采用者和合作方。
2. 主持式与自助合计累计达到100–150名独立体验者。
3. 取得25名7–14日内再次参与者；至少15人产生主动分享、转介、再次测试或其他可核实行动。
4. 再发布4–6件核心内容，继续使用已经有效的渠道，不再同时开新平台。
5. 合作交流累计达到10次，其中争取3项有明确下一步。
6. 完成目标对象、市场规模情景、竞争与替代、SWOT和商业方向比较。
7. 12月4日停止主要新增招募，转为回访和整理。

阶段交付：完整研究数量、漏斗数据、目标对象与场景、有效渠道、商业方向比较、至少一条“发现→修改→回测”记录。

### 阶段五｜12/05–31：分析、HKSTP报告和提交

目标：不再为了凑数新增大量研究，把已有资料变成可核查的结论和报告。

要做：

1. 12月5–11日完成必要回访、数据清理和最终市场评估。
2. 12月11日冻结用于主要报告的数据。
3. 12月7–16日制作5分钟以内Pitch影片。
4. 12月14–18日完成报告、影片和行政附件审核。
5. 12月21–23日完成内部提交目标并保存发件／收件记录。
6. 12月24–31日只处理补件和修改，12月31日为正式截止日。

## 3. 营销漏斗：建立认知之后让人走到哪里

这条漏斗从10月PoC出现后正式运行。数字是本季度的工作目标，不是行业基准；10月16日和11月13日根据真实转化率修正。

| 漏斗阶段 | 到12月4日目标 | 怎么做 | 记录什么 |
|---|---:|---|---|
| 看到 | 10,000次相关曝光 | 6件核心内容、约10–14件由核心素材拆出的短内容、相关社群／活动发布、定向转发与外联 | 来源、内容、曝光；不把曝光写成用户 |
| 进一步了解 | 1,000次介绍页访问或完整长视频观看 | 所有内容指向同一介绍／参与入口 | 访问、完整观看、来源 |
| 自愿留下联系方式 | 200人 | 测试报名、更新订阅或合作联系分开选择，不自动订阅 | 同意类型、来源、希望参与什么 |
| 实际体验PoC | 100–150名独立体验者 | 主持式测试＋自助体验；同一人去重 | 版本、任务、是否完成、是否需要协助 |
| 再次参与 | 25人 | 版本更新、回测邀请、后续体验；主动回来与提醒回来分开 | 时间间隔、触发原因、做了什么 |
| 主动传播／转介 | 15人 | 提供可分享材料和明确的邀请方式，不购买好评 | 分享、转介、组织体验或公开内容 |
| 具体合作 | 10次交流，3项下一步 | 用实际PoC和对应场景接触相关组织或个人 | 对象、场景、反对意见、约定日期 |

为了完成漏斗，10月至12月4日安排：

- 每两周制作1件核心材料，共6件左右。
- 每周从真实素材中整理1–2件短内容，不要求日更。
- 每周进行约4次定向外联，总计约40次。
- 争取4次由社群、活动方、内容创作者或合作方帮助分发／展示的机会。
- 安排2次集中的线下或活动式快速访问；没有合适场地时改为线上统一材料测试。

## 4. 这些数字怎样得来

- **深度访谈36人：**研究显示，较集中的单一研究对象常在约16–24次访谈后才达到较深入的“意义饱和”。CubeEngine涉及不同阶段和不同经验角色，因此用三轮共36人，而不是用12人完成整个项目研究。
- **PoC主持测试40人次：**每个版本／主要任务以5–8人快速发现问题，再修改再测；40人次允许覆盖多个版本、任务和回测，而不是一次召集40人。
- **焦点小组4组：**每组6–8人。四组用于比较不同经验背景和前后阶段，同时仍在一人团队可以整理的范围内。
- **问卷300份：**足够做整体方向和少量分组比较，但如果通过自愿参与和社群转发获得，它仍然不是随机样本，不能用传统抽样误差声称代表整个市场。
- **快速访问150人：**可以把三种说明／内容各测试约50人，用来发现明显的理解和记忆差异；它回答第一反应，不回答长期需求。
- **100–150名体验者：**采用旧计划100–500测试者区间的低端，更符合当前PoC、承接能力和20小时／周Marketing投入；得到真实运作信号后再决定是否扩大。

数字依据参考：[访谈的代码饱和与意义饱和研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC9359070/)、[定性研究样本量系统综述](https://doi.org/10.1016/j.socscimed.2021.114523)、[NN/g定性可用性测试人数](https://www.nngroup.com/articles/how-many-test-users/)、[CDC焦点小组方法说明](https://www.cdc.gov/field-epi-manual/php/chapters/qualitative-data.html)、[Pew对概率与非概率调查的说明](https://www.pewresearch.org/short-reads/2018/08/06/what-are-nonprobability-surveys/)。这些资料提供起点，最终人数仍要结合研究问题、对象差异和实际新增信息调整。

## 5. 两人不到的团队怎样完成

本计划按Founder每周20小时、约15周、最多约300小时设计；不要求CTO固定投入。Founder时间分配如下：

| 工作 | 总工时上限 |
|---|---:|
| 招募、访谈、快速访问、焦点小组和PoC测试 | 135小时 |
| 内容、介绍页、外联和参与者关系 | 85小时 |
| 每周分析、市场研究和策略调整 | 35小时 |
| HKSTP报告、影片和行政资料 | 30小时 |
| 延误与故障缓冲 | 15小时 |
| 合计 | 300小时 |

CTO如能协助，优先承担：技术背景参与者招募、部分技术访谈、PoC问题说明和版本核对。CTO的时间用于提高质量或冲击100–150体验者的上限，不作为完成最低有效线的前提。

每周只维持五个固定动作：

1. 招募和预约。
2. 完成当周访谈／测试／快速访问。
3. 整理原话、行为和数字。
4. 制作或发布一批共用素材。
5. 周末用一小时决定下周继续、修改或停止什么。

若时间不足，削减顺序是：新增平台→额外内容→第四组焦点小组→超过200份后的问卷→超过100人的自助体验。优先保留深度访谈、PoC测试、再次参与记录和HKSTP证据。

## 6. 预算

访谈和问卷本身不要求购买工具；现有表单、视频会议和表格即可。真正的现金成本是难招对象的感谢费、线下交通／材料和提高问卷完成率的奖励。

| 用途 | 上限 |
|---|---:|
| 难招募访谈／PoC参与者感谢费 | HK$1,200 |
| 问卷小额抽奖或感谢 | HK$300 |
| 两次线下快速访问的交通、打印或简单材料 | HK$300 |
| 应急 | HK$200 |
| 合计 | HK$2,000 |

不为所有参与者付费。感谢费优先给需要专业经验、投入时间较长或需要多次回访的人。若要购买专业样本库或付费问卷面板，HK$2,000通常不足，应单独增加预算，不能从当前计划中假装解决。

## 8. 数字使用规则

- 同一个人可以参加访谈、PoC和回访，但独立人数只算一次。
- 主持式测试、自助体验、观看影片和填写问卷分别记录，不能互相冒充。
- “有效问卷”必须完成关键题、符合筛选条件、没有明显重复或乱填。
- 街头／活动快速访问必须使用同一材料和同一组核心问题，否则不能合并比较。
- 10月16日和11月13日必须按实际招募率、完成率和工作量调整后续数字，并保留调整理由。
- 这些数字用于安排工作和形成方向性证据，不足以单独宣布完整市场需求、代表性结论或PMF。
