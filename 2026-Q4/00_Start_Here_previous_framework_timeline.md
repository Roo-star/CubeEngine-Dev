执行期：2026-09-16—2026-12-31｜当前版本：2026-09-17

## 1. 当前项目是什么

- **CubeUniverse**是统一、连贯的IP：它承载“把熟悉的平面规则带入新的空间维度”这一思想，以及由此产生的技术、玩法、作品和合作可能。
- **CubeEngine**是当前研发和市场验证的核心。9月底至10月初要验证的是引擎PoC，不是已经定型的游戏合集App。
- **多款转换Demo**用于证明CubeEngine不只适用于一个游戏，也不是分别手工制作的孤立案例。
- **Providence**是CubeUniverse中的原创作品，用来展示这套思想能够支持怎样更完整的体验；它不能代替CubeEngine验证。
- 集成App、开发工具、授权服务、原创游戏发行等都是未来可能的商业方向。本阶段可以收集证据，但不由Marketing提前决定最终产品形态。

## 2. 12月底前要完成什么

本阶段不是要证明完整PMF，也不是要完成大规模发行。12月底前需要形成以下五类结果：

| 结果 | 到12月底应能说清楚什么 |
|---|---|
| 项目认知 | 外部人能否理解CubeUniverse在探索什么，以及CubeEngine与Demo、Providence的关系 |
| 引擎可信度 | 哪些真实材料能够证明CubeEngine是一套可重复工作的系统，而不只是几个3D游戏Demo |
| 体验价值 | 哪些升维变化带来了可理解、有意义或值得继续体验的玩法，哪些只是视觉新奇或增加负担 |
| 市场方向 | 哪些人在哪些场景下最能理解、使用、传播或推动这个项目；仍然存在什么反例与未知 |
| HKSTP交付 | 用指定模板呈现原计划、实际进展、研究方法、数据、调整过程、资源和下一步，并提交5分钟以内影片及所需附件 |

本阶段最低完成标准：有真实PoC、有真实外部反馈、有至少一条“发现问题→修改→再次验证”的完整记录，并且所有对外陈述都能区分“已经实现、实验中、未来方向”。

## 3. Research、Promotion和交付怎样配合

三条工作同时进行，不是先把研究全部做完，再开始宣传。

```text
提出当前最重要的问题
→ 找真正有相关经验的人
→ 用概念、影片或PoC取得反馈
→ 记录对方说了什么、做了什么
→ 修改产品、展示顺序或市场表达
→ 再验证
→ 证据成熟后扩大公开和合作接触
```

| 工作线 | 主要作用 | 本阶段包含什么 |
|---|---|---|
| 用户与市场研究 | 减少错误判断 | 研究问题、受访对象选择、访谈、PoC观察、必要时的短问卷、竞品与市场研究、分析和市场评估 |
| Promotion与品牌 | 建立理解、记忆、信任和参与 | Promotion策略、统一叙事、PoC证明材料、分层亮相、社媒／社群／活动选择、外部关系和IP阶段性发布 |
| 保护与HKSTP交付 | 保护可公开边界并保存证据 | 专利材料与既有披露清单、展示边界、研究记录、版本记录、报告、影片和行政附件 |

同一次PoC展示可以同时产生研究和传播价值，但必须分开记录：研究回答“我们学到了什么”，Promotion回答“别人是否理解、记住并采取了下一步行动”。

## 4. 已确定和暂不确定的事项

### 已确定

- CubeUniverse保持一个统一IP，不拆成互不相关的品牌。
- CubeEngine引擎PoC是本阶段的核心实物与测试节点。
- 9月底至10月初争取提供可操作版本、多个转换Demo和真实演示录屏。
- Marketing由Founder每周投入约20小时；CTO是可选协助，不把其时间预先算作固定产能。
- Marketing现金支出控制在HK$2,000以内；专利、研发和正式上架费用另算。
- 12月31日为HKSTP正式截止日，12月23日为内部提交目标。

### 必须根据证据再决定

- 最优先服务、传播或合作的对象。
- 最终商业模式和产品形态。
- 是否以及何时做问卷。
- 社媒主渠道、是否开Discord、是否做线下活动。
- 是否在App Store、Steam或其他平台公开分发。
- 是否参加具体比赛、展会或会议。
- 第一次大范围公开亮相的日期和内容。

这些事项没有被取消，只是不在证据不足时写成既定战略。

## 7. 公开亮相必须满足的条件

不是等所有研究完成才公开，但公开范围必须随证据成熟度增加。

### 可以先做小范围展示的条件

- 清楚标明当前版本和未完成能力。
- 展示内容不超过已确认的专利／披露边界。
- 参与者知道这是研究或PoC，而不是完成产品。
- 有办法记录反馈、问题和版本。

### 可以做第一次较公开亮相的条件

- PoC可以在非开发环境稳定完成所展示的核心流程。
- 不熟悉项目的人能基本说清“这是CubeEngine，不是一款孤立的3D小游戏”。
- 至少能用两个机制不同的案例支持“可重复能力”，或明确承认当前只证明到哪里。
- 已确定一个主要参与入口，例如申请测试、观看完整演示或提出合作场景。
- 团队有能力回应报名、问题和故障，不会发布后无人承接。

条件不满足时，可以继续做受控测试和概念表达，不把延期理解为Marketing停止。

## 8. 本阶段默认不做什么

- 不做300份街头快速问卷。
- 不预设15–30次访谈、6–10个焦点小组或固定玩家／创作者比例。
